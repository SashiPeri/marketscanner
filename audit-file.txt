## 3. Sierra verdict (critical)

- Interface actually used: DTC binary TCP to a locally-run Sierra Chart DTC server (`127.0.0.1:11099` default). Items 2/3 in the panel (`HTTP_SERVER`, `FILE_SYNC`) are STUB — UI options with no backend implementation; backend always speaks DTC regardless of `connectionType`.
- Is DTC capable of CME data? YES — protocol is not the blocker. DTC is Sierra's native real-time + historical-tick protocol; `docs/SIERRA_INTEGRATION.md` correctly identifies it as primary for live tape with Historical Price Data as secondary. No evidence of relying on a Sierra-restricted capability.
- But the current implementation cannot deliver CME data: (a) blank `Exchange[16]` on every `MARKET_DATA_REQUEST` (adapter never populates `subscription.exchange` or `dtcConfig.exchange`); real Sierra needs `ESZ25-CME`-style symbol + `CME` exchange — expect `103/121 REJECT`, which are swallowed. (b) No contract/expiry mapping (`"ES"` sent verbatim). (c) No auto-connect/subscribe — ES/NQ never requested without manual sync. (d) Depth never subscribed on first connect (only on reconnect). (e) No CME entitlement check; user must run Sierra Chart locally with DTC enabled + paid CME feed — heavy but viable single-trader path, undocumented in-app (panel help mentions port 8080, contradicting 11099 default).
- Does it ever receive a genuine ES/NQ update? No evidence anywhere: no logs, dumps, or tests; `ES/NQ` appear only as mock seeds, test symbols, or `App.tsx:32` default selection. `codec.test.ts` uses synthetic `Buffer.alloc`; `providerAdapter.test.ts` tests baseline mapping only.
- Can the architecture support it without bloat? Yes. Provider-agnostic `MarketSnapshot/TradePrint/OrderBookSnapshot` contract is sound; fix is small: populate exchange + symbol translation + auto-connect/subscribe + surface rejects + kill fake seeds. No Redis/ACSIL/DLL needed this week.
- BLOCKER formulation: not "DTC is unsupported" — DTC is the right path. The blocker is "current DTC subscriber cannot route CME subscriptions (blank exchange, no contract mapping) and has never proven one real print, so the live path is BLOCKED until those two are fixed and validated against a real Sierra instance."
